# Facilitator Guide
**Workshop:** Getting Started with Git and GitHub: From Zero to Your First Repository  
**Duration:** 3 Hours (180 Minutes)  
**Target Audience:** Beginners at Kyambogo University  

---

## Pre-Workshop Checklist (1 Week to 1 Day Before)
- [ ] Confirm a venue at Kyambogo University with enough seating, power outlets, and a working projector.
- [ ] Test campus Wi-Fi or arrange a backup mobile hotspot for the demonstration laptop.
- [ ] Verify Git, VS Code, and a test GitHub account work smoothly on the facilitator's computer.
- [ ] Confirm the `demo-project` repository is public and ready for live demos and pair exercises.
- [ ] Share the workshop announcement early and ask attendees to create a free GitHub account beforehand.
- [ ] Arrange shared computers or pair seating for students attending without personal laptops.
- [ ] Print or share links to the Command Reference Sheet, Practical Exercise Sheet, and Feedback Form.
- [ ] Brief KYUCSA / Concept Crashers volunteers so they know how to assist beginners without taking over their keyboards.

---

## Workshop Run-of-Show (180 Minutes)

| Time | Duration | Activity | Facilitator Focus |
| :--- | :---: | :--- | :--- |
| **0:00 – 0:10** | 10 min | **1. Welcome & Introduction** | Welcome attendees, share learning objectives, and do a quick show-of-hands check on prior Git/GitHub experience. |
| **0:10 – 0:20** | 10 min | **2. Introduce the Problem** | Discuss the "final_project_v2" file-copying problem and how group file sharing breaks down without version control. |
| **0:20 – 0:35** | 15 min | **3. Git & GitHub Concepts** | Walk through Git vs. GitHub, Repository, Commit, Branch, and Pull Request using everyday analogies. |
| **0:35 – 0:55** | 20 min | **4. Live Demonstration** | Create `my-first-project` live on GitHub, edit `README.md`, commit, and inspect commit history. |
| **0:55 – 1:20** | 25 min | **5. Hands-On: First Repository** | Walk around the room helping attendees create and edit their own repositories. Do not rush beginners. |
| **1:20 – 1:40** | 20 min | **6. Commits & Terminal Basics** | Demonstrate `git --version`, `git config`, `git clone`, `git status`, `git add`, `git commit`, and `git push`. |
| **1:40 – 1:50** | 10 min | **7. Short Break** | Rest break; assist anyone stuck on Git installation or account login. |
| **1:50 – 2:10** | 20 min | **8. Branches & Pull Requests** | Explain why we protect `main`, create a branch live, make a small edit, and open a Pull Request. |
| **2:10 – 2:30** | 20 min | **9. Pair Collaboration Exercise** | Pair up students on `demo-project` so one opens a PR on a branch and the partner reviews and merges it. |
| **2:30 – 2:45** | 15 min | **10. Final Practical Challenge** | Have attendees create a new project repo with a structured `README.md` and meaningful commit message. |
| **2:45 – 3:00** | 15 min | **11. Feedback & Closing** | Share feedback using *I Like, I Wish, What If*, share next-step resources, and hold 5 minutes for the feedback form. |

## Troubleshooting Guide During the Session

| Issue | Recommended Action |
| :--- | :--- |
| **Attendee has no GitHub account** | Help them sign up quickly or pair them with a neighbour so they can follow along and register after the session. |
| **Git is not installed locally** | Let them complete all exercises directly in the GitHub web interface so they still learn repos, commits, branches, and PRs. |
| **Slow or unstable internet** | Switch to local slides and offline terminal demonstrations until connectivity stabilizes. |
| **Attendee has no laptop** | Pair them with another student or assign a shared lab machine, ensuring both partners take turns typing. |
| **Terminal shows an error** | Read the error message together with the student and explain what caused it instead of typing the fix for them. |

---

## Facilitator Feedback Guidelines
- **During Labs:** Use **Appreciation** (celebrate their first commit/PR), **Coaching** (guide with questions rather than taking over their mouse), and **Evaluation** (verify each repo has a README and commit history).
- **After the Session:** Review participant feedback forms with volunteers using **Red, Yellow, Green** (what worked well, what needs tweaking, and what failed) and save notes for the next KYUCSA workshop.
